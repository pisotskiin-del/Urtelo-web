# teplo-web

Веб-приложение на Django, которое заменит программу Urteplo на Visual FoxPro 9
(`D:\teplo_dog\urteplo.exe`). Сейчас это первый этап: модели всех таблиц базы
`D:\teplo_dog\dbf\ur_teplo.dbc`, перенос данных со сверкой, вход по ролям и экраны
справочников из меню «Справочники» старой программы, карта абонента, расчёт
начислений, переход на новый месяц с архивом и выгрузкой в 1С, отчёты форм «Отчеты»
и «Печать», документы абонентам («Информация-счёт», акт) с почтовой рассылкой, отчёты
за период, приём показаний приборов из КРЭДО. Что ещё не перенесено — в конце
[ЗАМЕЧАНИЯ.md](ЗАМЕЧАНИЯ.md).

Открытые вопросы и найденные расхождения в данных описаны в [ЗАМЕЧАНИЯ.md](ЗАМЕЧАНИЯ.md).

## Что есть

- **Модели по настоящим таблицам.** `catalogs/models.py` построен командой `dbf_inspect`
  по 99 таблицам из `D:\teplo_dog\dbf`: 77 таблиц базы `ur_teplo.dbc` и 22 свободные.
  Не переносятся временная `poisk_ab` и неиспользуемая `sul` (улицы).
  Имена таблиц и полей сохранены как в DBF. Полные имена полей длиннее 10 символов
  взяты из `ur_teplo.dbc`, при этом соответствие колонке DBF хранится в `dbf_columns`.
- **Названия по-русски.** Названия справочников взяты из меню программы
  (`MENUS\gl_menu.mpr`), подписи полей из заголовков столбцов форм (`Forms\*.scx`).
  Они хранятся в `dbfsync/labels/ur_teplo.json`, и для каждой таблицы указан источник.
- **Ключи и связи.** 3 ключа и 47 связей `ForeignKey` (на города из `danrasch`, министерства и
  потребителей) заданы в `dbfsync/labels/ur_teplo_relations.json`. Каждая связь
  проверена на данных: у любой ссылки есть пара, а 0 или пустое значение означает,
  что ссылки нет.
- **Перенос данных.** Команда `dbf_import` загружает записи (удалённые в DBF не
  переносятся), сверяет их число с DBF и сообщает о нечитаемых значениях. Оригинальные
  файлы только читаются.
- **Роли.** Администратор (всё, включая пользователей и админку), Оператор
  (просмотр, добавление, изменение), Наблюдатель (только просмотр).
- **Карта абонента** (`/abonents/`, меню «Абоненты» → «Карта абонента», форма `karta`).
  Поиск в выбранном городе по № договора и по наименованию (без учёта регистра и
  пробелов, как в старой программе) и по лицевому № во всех городах. Карта показывает
  шапку (город, расчётный месяц, договор, наименование, министерство, категория,
  котельная) и вкладки «Отопление», «ГВС», «Исходные данные» с подписями из старой формы,
  переход к первой, предыдущей, следующей и последней записи города, ссылки на
  присоединённые объекты и «Карту договора» (форма `karta_dog`) с итогами. Правка по
  вкладкам: поля, которые в старой форме заполнял расчёт, только показываются. Удаляет
  только Администратор. Ввод нового абонента (форма `nov_abonent`), тепловые потери по
  участкам с кнопкой «Расчитать» (`kalcul_poteri`) и информация по теплосчетчику
  (`teploschetchik`). Расположение полей задано в `abonents/layout.py`.
- **Расчет начислений** (`/abonents/raschet/`, кнопка «Расчет» карты, `abonents/raschet.py`).
  «Исходные данные для расчета» (форма `dan_rasch`): температура, t коэффициент, дни
  отопления и ГВС, Q факт по городу. Расчет по всем абонентам всех городов в том же
  порядке шагов, что в старой программе: потери, начисления по прибору и по нагрузке,
  присоединённые приборы и нагрузки, субабоненты договора, начислено по факту,
  предъявлено к оплате, объекты одного договора, лимиты. Рассчитываются только
  заключённые договоры, ГВС по прибору — по счетчику (× 0,0533 Гкал). После расчета — итоги по
  городам и список абонентов, у которых заканчивается лимит.
- **Переход на новый месяц** (`/abonents/nov-mes/`, меню «Новый месяц», форма `nov_mes`,
  `abonents/nov_mes.py`). Закрытый месяц сохраняется в архиве (вместо файлов
  `Arhiv\Po/Da/Ot/taММГГГГ.dbf` — запись «Архив месяца» в базе), заполняется таблица
  `abot` и файл выгрузки в 1С `Abpt<ГГ><ММ>.dbf` (скачать или в папку из «Справочники» → «Настройки программы»), накапливается выставленное с начала финансового года и отопительного
  сезона, пересчитывается остаток лимита, начисления, потери ГВС и дни обнуляются, предыдущие
  показания отопления и ГВС становятся равны настоящим, во всех городах открывается следующий месяц.
  Выполняет только Администратор; последний переход можно отменить.
- **Отчеты и печать** (`/abonents/otchety/`, меню «Отчеты», `abonents/reports.py`):
  кнопки формы «Отчеты» (распределение по бюджетам, расшифровка по министерствам,
  ведомость по приборам, без начисления, превышение лимита, потребление и нагрузка по
  котельным, нагрузка по категориям, полезный отпуск, нагрузка по министерствам,
  потребление по приборам учета, поверка приборов) и меню «Печать» (паспорта
  готовности, потребители по котельным, часовые нагрузки по категориям). Отчет
  открывается на экране с выбором города и параметров, печатается кнопкой «Печать»
  (без меню и кнопок) и выгружается в Excel.
- **Документы абонентам** (`abonents/documents.py`): «Информация-счёт» и «Акт о фактическом
  потреблении» по договору за текущий месяц — кнопки «Счёт» и «Акт» в карте абонента и
  договора, пакет по всем договорам участка в «Отчетах». PDF строится на сервере и хранится
  по месяцам (`TEPLO_DOC_DIR`). За закрытый месяц документ строится по архиву месяца
  (выбор «Месяц» на странице документа, в пакете и в рассылке): начисления и тарифы — на
  момент закрытия; если в архиве старой программы нет тарифов — по нынешним, с пометкой.
- **Почтовая рассылка** (`abonents/pochta.py`): рассылка документов отмеченным договорам
  участка и отправка одного документа, реестр отправленных писем с ошибками и PDF.
  Настройки почты — «Настройка рассылки писем», пароль — `TEPLO_SMTP_PASSWORD`.
- **Ведомости, реестры** (группа в «Отчетах»): реестр действующих договоров, ведомость
  отправленных писем за месяц (по реестру писем), нагрузка котельных по категориям
  (отопление и ГВС).
- **Отчеты за период** (группа «Архив (за период)» в «Отчетах», `abonents/arhiv.py`):
  полезный отпуск за период, расшифровка отпуска по лицевому, потребление бюджета за год —
  по закрытым месяцам. Месяцы, закрытые в старой программе, загружаются командой
  `arhiv_import` (см. ниже).
- **Показания приборов из КРЭДО** (`/abonents/kredo/`, меню «КРЭДО» слева,
  `abonents/kredo.py`, кнопки формы `rric`): показания приборов учёта абонентов участка за
  текущий месяц принимаются из АПК «КРЭДО» (процедура `Kredo_DeviceMeters_Info` через
  COM-объект РРИЦ, только Windows, `pywin32`) или из файла ответа XML, показываются рядом
  с картами и разносятся в отмеченные лицевые (`pok_new`, `date_pok`). Показание меньше
  того, что в карте, — только после подтверждения. Ответ сервиса и что изменено хранятся
  в базе. Из командной строки: `python manage.py kredo_pokazaniya --gorod 1` (только приём).
  Сертификат участка ищется в хранилище пользователя Windows, под которым запущена программа.
- **«Информация-счёт» через КРЭДО** (`abonents/kredo_dok.py`, как `infch_kredo_kr`): кнопки
  «В КРЭДО» и «Подписать (проверка)» на странице «Информации-счёта» и рассылка через КРЭДО
  («Отчеты» → «Рассылка через КРЭДО»). Документ подписывается крипто-модулем РРИЦ сертификатом
  участка (со штампом времени `TEPLO_KREDO_TSA`), копия XML сохраняется рядом с PDF, затем
  `Set_URDocument`. Получатель — коды `org_in`, `pid_in` в карте (вкладка «КРЭДО»), отправитель —
  «Настройки программы». Каждая попытка — в реестре писем (канал «КРЭДО»). Из командной
  строки: `python manage.py kredo_schet --gorod 1 --dog 19 --proverka`. Сертификаты, их
  отпечатки и коды отправителя по участкам — в «Справочники» → «Настройки программы».
- **Коды абонентов в КРЭДО** (`/abonents/kredo/kody/`, меню «КРЭДО» слева, кнопка
  «Коды КРЭДО» в карте): список организаций КРЭДО, подбор организации по фискальному коду
  или названию и представителя, запись `org_in`, `pid_in`, ФИО и должности в карту.
- **Экраны справочников.** 14 справочников в порядке меню программы (без неиспользуемых «Улиц») и новые «Подписанты документов» (кто утверждает и подписывает отчеты; запись с участком заменяет общую для этого участка) и «Настройки программы» (папка для выгрузки в 1С, меняет только Администратор): таблица с поиском,
  сортировкой и постраничным выводом, карточка записи, добавление, правка, удаление.
  Кнопки видны только тем, кому это разрешено ролью. «Настройка рассылки писем»
  хранит пароль почты, поэтому она доступна только в админке, а пароль там скрыт.
- **Админка Django** (`/admin/`) со всеми 99 таблицами.

## Установка (Windows)

Проще всего двойным щелчком: сначала `install.bat` (один раз). Он создаёт ярлык
«Теплоснабжение» на рабочем столе и в меню «Пуск». Ярлык запускает приложение как
обычную программу (`teplo.pyw`): сервер работает без окна консоли, а приложение
открывается в отдельном окне Edge, Chrome или Яндекс Браузера без адресной строки и вкладок. Закрыли
окно — сервер остановился. Если приложение уже установлено, ярлык создаёт `shortcut.bat`.

`run.bat` делает то же, что ярлык. Ошибки запуска записываются в `teplo.log`.
Обновление: распакуйте новую версию поверх папки и запустите `update.bat` — данные
сохраняются.

При запуске 3 секунды показывается заставка «Система расчётов с юридическими
потребителями» с логотипом, затем под логотипом появляется вход. Логотип предприятия:
положите файл `static/img/logo.png` (или `logo.svg`, `logo.jpg`); пока его нет,
показывается значок программы.

Горячие клавиши: <kbd>/</kbd> — поиск по наименованию в списке абонентов,
<kbd>PageUp</kbd>/<kbd>PageDown</kbd> в карте — предыдущая и следующая запись.

Если запускаете команды вручную, вводите их в окне «Командная строка» по одной, а не
сохраняйте в .bat: в .bat-файле строка `.venv\Scripts\activate` без `call` завершает
весь файл.


Подходит Python 3.8 или новее (на 3.8–3.9 ставится Django 4.2, на 3.10+ более новый).
Для тестов нужен `requirements-dev.txt`, для PostgreSQL — `requirements-postgres.txt`. Распакуйте проект в отдельный каталог, например
`D:\teplo_dog_web`, а не в папку программы.

```bat
cd D:\teplo_dog_web
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

python manage.py migrate
python manage.py init_roles
python manage.py dbf_import --dir D:\teplo_dog\dbf
python manage.py add_user admin --role admin --password СложныйПароль1 --name "Иванов И.И."
python manage.py runserver
```

Откройте http://127.0.0.1:8000/ и войдите под созданным пользователем.
Чтобы приложение было доступно с других компьютеров локальной сети, запустите
`python manage.py runserver 0.0.0.0:8000` и добавьте имя или IP-адрес сервера в
переменную `DJANGO_ALLOWED_HOSTS` (см. `.env.example`).

Другие пользователи:

```bat
python manage.py add_user oper --role operator --password Пароль123
python manage.py add_user view --role viewer --password Пароль123
```

`dbf_import` только читает DBF и при каждом запуске заново заполняет таблицы
приложения. Чтобы не ловить таблицы в момент записи старой программой, лучше
загружать данные из копии папки `dbf`.

Архивы месяцев старой программы для отчетов за период (файлы `PoММГГГГ.dbf`,
`DaММГГГГ.dbf`, `tarММГГГГ.dbf` или `taММГГГГ.dbf`) загружаются отдельно, один раз:

```bat
python manage.py arhiv_import --dir D:\teplo_dog\Arhiv
```

Месяцы, которые уже есть в архиве, пропускаются; закрытые в новой программе не
заменяются никогда. Повторно загрузить месяцы старой программы — `--zamenit`.

Показания приборов из старой программы (только поля показаний, остальное в новой
программе не меняется) — сначала посмотреть, что изменится, потом записать:

```bat
python manage.py pokazaniya_import --dir D:\teplo_dog\dbf
python manage.py pokazaniya_import --dir D:\teplo_dog\dbf --zapisat
```

## Если структура таблиц изменилась

```bat
python manage.py dbf_inspect --dir D:\teplo_dog\dbf --output catalogs\models.py
python manage.py makemigrations catalogs
python manage.py migrate
python manage.py init_roles
python manage.py dbf_import --dir D:\teplo_dog\dbf
```

Исправления данных при загрузке (например, «Акцепт» 0 → 1) задаются в
`dbfsync/labels/ur_teplo_fixes.json`; `dbf_import` пишет, сколько значений исправлено.

`catalogs/models.py` вручную не правится. Названия меняются в
`dbfsync/labels/ur_teplo.json`, а ключи и связи — в `ur_teplo_relations.json`.
После правки запустите `dbf_inspect` снова. Кодировка каждой таблицы (cp1251 или
cp866) определяется по её заголовку, а если там пусто, то по самим данным.
Порядок справочников на главной странице задаётся в `catalogs/registry.py`.

## PostgreSQL

По умолчанию используется SQLite (файл `db.sqlite3`), чтобы ничего не настраивать.
Для PostgreSQL задайте переменные `DB_ENGINE=postgresql`, `DB_NAME`, `DB_USER`,
`DB_PASSWORD`, `DB_HOST`, `DB_PORT` и выполните шаги установки. Для больших объёмов
есть отдельный инструмент переноса через COPY с подробной сверкой: `migration/dbf2pg`.

## Работа на сервере Server-b (Windows Server 2016, 10 операторов)

Операторы входят на `\\Server-b` через удалённый рабочий стол, у каждого в его учётной
записи стоит свой сертификат. Поэтому у каждого запускается своя копия программы под
его учётной записью (подпись в КРЭДО — его сертификатом), а база одна — PostgreSQL на
том же сервере.

1. **PostgreSQL 15.** Новее для Windows Server 2016 установщик EDB не проверяется, 15-я
   поддерживается до ноября 2027 г. Установщик с postgresql.org, порт 5432, служба
   запускается сама. В pgAdmin или `psql -U postgres`:
   `CREATE USER teplo PASSWORD '…'; CREATE DATABASE teplo OWNER teplo ENCODING 'UTF8' TEMPLATE template0;`
   Доступ из сети не нужен: программа на том же сервере (`localhost`).
2. **Программа.** Python 3.13 «для всех пользователей» (галочка *Install for all users*).
   Папку программы скопировать на сервер, например в `D:\teplo-web`, там `install.bat`,
   затем `.venv\Scripts\pip install -r requirements-server.txt`. Операторам нужно право
   чтения на папку, а на папку документов — запись. В `.env`:
   ```
   DB_ENGINE=postgresql
   DB_NAME=teplo
   DB_USER=teplo
   DB_PASSWORD=…
   DB_HOST=localhost
   DJANGO_DEBUG=0
   DJANGO_SECRET_KEY=<длинная случайная строка>
   TEPLO_PORT=auto
   TEPLO_DOC_DIR=D:\teplo_dokumenty
   ```
   и `.venv\Scripts\python manage.py collectstatic --noinput`.
3. **Перенос данных** из нынешней базы (программа на старом компьютере закрыта), в пустую базу:
   `.venv\Scripts\python manage.py perenos_v_postgres --iz <путь>\db.sqlite3`.
   Команда создаёт таблицы, переносит всё (абоненты, справочники, архивы, реестр писем,
   пользователи), обрезает строки длиннее поля и сверяет число записей каждой таблицы.
4. **Ярлык каждому оператору**: войти под ним и выполнить
   `D:\teplo-web\.venv\Scripts\python D:\teplo-web\teplo.pyw --shortcut`. С `TEPLO_PORT=auto`
   ярлык запускает копию сервера оператора на свободном порту, окно программы и журнал —
   в `%LOCALAPPDATA%\Teplo` этого оператора. Закрыл окно — его копия остановилась.
5. **КРЭДО.** На сервере должен быть установлен и зарегистрирован крипто-модуль РРИЦ
   (`RRIC_COM_OBJECT`) и сертификат службы «Rric Wcf Service». Окно выбора сертификата
   появляется в сеансе того, кто нажал кнопку.
6. **Обновление программы** — когда все вышли: заменить файлы, `update.bat`
   (применяет изменения базы), `collectstatic --noinput`.
7. **Резервная копия** — каждую ночь из Планировщика заданий:
   `"C:\Program Files\PostgreSQL\15\bin\pg_dump" -Fc -U teplo -f D:\teplo_backup\teplo_%date%.dump teplo`
   (пароль — в `%APPDATA%\postgresql\pgpass.conf` учётной записи задания).

Если когда-нибудь понадобится работать не через удалённый рабочий стол, а со своих
компьютеров: `server.bat` (или служба через NSSM) отдаёт программу по сети на порту 8000,
а ярлык на рабочем месте открывает её при `TEPLO_SERVER=http://Server-b:8000` в `.env`.
Подпись в КРЭДО при этом идёт там, где работает сервер, поэтому этот вариант годится
только без отправки в КРЭДО.

## Устройство проекта

| Каталог | Назначение |
|---|---|
| `teplo/` | настройки, адреса, поиск без учёта регистра по-русски для SQLite |
| `accounts/` | роли (`roles.py`), команды `init_roles` и `add_user`, страница входа |
| `abonents/` | карта абонента, поиск, карта договора |
| `catalogs/` | модели (генерируются), экраны справочников, регистрация в админке |
| `dbfsync/` | чтение DBF и .dbc, генерация моделей, загрузка данных |
| `dbfsync/labels/` | русские названия и связи таблиц Urteplo |
| `dbfsync/tests/` | автотесты переноса на выдуманных тестовых таблицах |
